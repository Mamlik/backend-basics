# Ревью openapi.yaml

1. URL используют существительные во множественном числе и kebab-case; возврат оформлен как `POST /loans/{id}/return`.
2. ID ресурса передаётся в path, фильтры — в query. Версия `/v1` указана в `servers`.
3. Описаны CRUD книг и читателей, создание, список, получение и возврат выдач.
4. Создание возвращает `201` с заголовком `Location`, удаление — `204` без тела.
5. Пустой список возвращает `200` с пустым `items`, а отсутствующий ресурс по ID — `404`.
6. Схемы запросов и ответов разделены; заданы типы, форматы, обязательные поля и ограничения.
7. Серверные поля помечены `readOnly` и исключены из запросов; `returned_at` допускает `null`.
8. Неизвестные поля запросов запрещены через `additionalProperties: false`; пустой PATCH не допускается.
9. Коллекции поддерживают фильтры и сортировку; `status=overdue` выбирает активные просроченные выдачи.
10. Пагинация использует `limit` и `offset`; значение limit по умолчанию — 20, максимум — 100.
11. Ошибки используют единый `ErrorResponse` с `code`, `message` и `request_id`; присутствуют все коды из задания.
12. Описаны наличие экземпляров, лимит пяти активных выдач, будущая дата возврата и запрет удаления при активных выдачах.
13. `available_copies` вычисляется сервером; повторный возврат не увеличивает количество экземпляров повторно.
14. Для `POST /loans` обязателен `Idempotency-Key`; описаны полный replay, конфликт тела, конкурентные повторы и TTL 24 часа.
15. У операций есть теги, `operationId` и описания; определения переиспользуются через `$ref`, приведены примеры запросов, ответов и ошибок.
16. Bearer JWT объявлен в `securitySchemes` и обязателен через глобальный `security`; описан ответ `401` с `WWW-Authenticate`.
17. Спецификация прошла валидацию OpenAPI 3.1; локальные ссылки и примеры соответствуют схемам.
