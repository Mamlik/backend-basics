# Правила API

1. Версия `/v1` задаётся в `servers`; в `paths` повторно её не добавляем.
2. URL — существительные во множественном числе и kebab-case. Осознанное действие возврата — `POST /loans/{id}/return`.
3. JSON-поля и query-параметры — snake_case; ID ресурса — в path, фильтры — в query.
4. GET читает, POST создаёт или выполняет действие, PATCH частично изменяет, DELETE удаляет. PATCH содержит хотя бы одно поле.
5. Ответы: 200 — чтение/изменение/возврат, 201 + Location — создание, 204 без тела — удаление. Ошибки используют 400/401/404/409/422.
6. Схемы запросов и ответов разделены. Запросы запрещают неизвестные и серверные поля через `additionalProperties: false`.
7. Все ошибки имеют `code`, `message`, `request_id`. Клиент ориентируется на стабильный `code`, а не текст сообщения.
8. Списки имеют фильтры, `sort`, `limit` (1–100, по умолчанию 20), `offset` (от 0), ответ `{items, total, limit, offset}`. Сортировка по умолчанию — id ASC.
9. Даты — YYYY-MM-DD, временные метки — RFC 3339 в UTC. null допустим только там, где явно указан в схеме.
10. Все операции требуют Bearer JWT; создание выдачи дополнительно требует Idempotency-Key с хранением результата 24 часа.
